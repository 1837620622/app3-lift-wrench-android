# 现场联调计划

## 目标

现场联调的目标不是直接施工验收，而是把通信链路、协议解析、曲线显示、数据库保存和导出证据逐条跑通。

## 联调前准备

- 安卓手机已开启 USB 调试。
- Android Studio 可安装调试包到真机。
- 手机能连接扳手 Wi-Fi。
- 扳手电量充足，避免自动休眠。
- 现场确认可以安全触发空载或低风险动作。
- App 正式界面不保留模拟模式，联调必须连接真实扳手或读取历史记录。

## 第一阶段：手机和 App

1. 安装调试 APK。
2. 打开 App，先检查当前 Wi-Fi、IP、网关和自动发现端点。
3. 确认连接扳手后能显示设备 SN 或设备应答。
4. 打开曲线全屏，确认曲线清晰。
5. 点击保存记录。
6. 进入历史页面，确认会话和点位存在。

## 第二阶段：Wi-Fi 和网络诊断

1. 手机连接扳手 Wi-Fi。
2. 检查当前 Wi-Fi 名称。
3. 检查手机本机 IP。
4. 检查默认网关。
5. 判断是否在 `192.168.4.x` 网段。
6. 尝试 ping `192.168.4.1`。
7. 尝试连接 `192.168.4.1:7888`。
8. 如果失败，自动尝试默认网关和候选协议端口。
9. 如果仍失败，手动输入 IP 和端口。

Android 当前尚未实现完整 Wi-Fi 诊断模块，该阶段需要补代码后再全自动执行。

## 第三阶段：TCP 和协议

1. 点击连接扳手。
2. 连接成功后立即发送心跳。
3. 观察是否收到 ACK 或其它帧。
4. 手动发送心跳，确认链路仍然可用。
5. 触发安全测试动作，捕获 `0x12` 扭矩角度过程帧。
6. 完成一次运行后，捕获 `0x15` 结果帧。
7. App 收到 `0x15` 后发送 `0x17` 确认。
8. 保存完整原始 HEX。

## 第四阶段：公式核对

1. 核对角度是否需要缩放。
2. 核对扭矩是否需要缩放。
3. 使用已知转角和导程检查位移。
4. 使用标定点检查顶升力。
5. 使用有效面积检查压力。
6. 记录平衡点附近的曲线形态。

## 第五阶段：稳定性

1. 连续采集一段时间。
2. 检查 TCP 是否断开。
3. 检查心跳是否保持。
4. 检查 App 是否卡顿。
5. 检查数据库是否持续写入。
6. 检查屏幕常亮策略和手机休眠策略。

## Kali 辅助方案

当 Mac 需要保持互联网给 Agent 使用时，可让 Kali 连接扳手 Wi-Fi：

```text
Mac 开发端
  -> SSH 到 Kali
  -> Kali wlan0 连接扳手 Wi-Fi
  -> Kali 转发或抓包
  -> Mac 继续联网开发
```

Kali 只用于调试，不作为正式 App 架构。

## 证据文件

联调完成后应保存：

- App 截图。
- 曲线截图。
- 原始 HEX 日志。
- 解析后的 CSV / Excel。
- 数据库导出。
- 当前 IP、网关、端口诊断结果。
- 协议帧通过清单。
- 公式复核记录。
