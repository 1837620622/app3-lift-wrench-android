# 厂家协议与通讯链路

## 正式链路

正式 App 不依赖 Kali：

```text
安卓手机
  |
  | 连接扳手 Wi-Fi
  v
扳手设备 192.168.4.1:7888
```

手机连接扳手 Wi-Fi 后通常没有互联网，因此 App 必须离线运行，不能依赖服务器、云数据库或在线接口。

## 调试链路

开发调试可使用 Kali：

```text
Mac 开发端
  |
  | SSH / 端口转发
  v
Kali 虚拟机
  |
  | wlan0 连接扳手 Wi-Fi
  v
扳手设备 192.168.4.1:7888
```

Kali 只用于抓包、转发和协议验证，不进入正式软件架构。

## 默认连接参数

```text
默认 IP：192.168.4.1
默认端口：7888
协议：TCP 二进制字节流
```

端口不是界面写死值，必须允许用户手动修改。现场若默认 IP/端口失败，应先检查手机是否仍在扳手 Wi-Fi 网段，再检查网关、ping 和 TCP 端口。

现场调试要注意：Wi-Fi 已显示连接并不等于设备 IP 已可通信。Kali 复测中出现过 `wlan0` 已连接 `500banshou`，但邻居表里 `192.168.4.1 FAILED`，这时 ping 和 TCP 会失败；重新触发 ARP 后邻居表恢复 `REACHABLE`，心跳和 SN 查询正常。

Android 端已加入网络诊断和自动发现：

- 当前 Wi-Fi 名称。
- 本机 IPv4。
- 默认网关。
- 是否进入 `192.168.4.x` 网段。
- 设备 IP 是否可达。
- 默认设备端口是否可连接。
- 默认地址失败后，自动尝试当前默认网关。
- 默认网关仍失败时，在 `192.168.4.x` 网段扫描候选协议端口 `7888/8899/9000/10001`。

Android 的 `InetAddress.isReachable()` 受系统限制，不能完全等价桌面系统 `ping`；正式判断优先看 TCP 端口和协议回包。

## 基础帧格式

```text
C5 C5 | 地址码 | 功能码 | FF FF | 数据长度 | 数据内容 | 校验码
```

字段说明：

| 字段 | 长度 | 当前处理 |
|---|---:|---|
| 帧头 | 2 | 主协议使用 `C5 C5` |
| 地址码 | 1 | App 发送默认 `0x01` |
| 功能码 | 1 | 按厂家功能码解析 |
| 保留位 | 2 | 默认 `FF FF` |
| 数据长度 | 1 | 最大 255 字节 |
| 数据内容 | N | 随功能码变化 |
| 校验码 | 1 | 单字节累加和 |

校验规则：

```text
checksum = sum(frame_without_checksum) & 0xFF
```

## 已实现功能码

| 功能码 | 名称 | 方向 | 当前处理 |
|---|---|---|---|
| `0x01` | 停止/正转/反转 | App 到扳手 | 可组包发送，正式现场需二次确认 |
| `0x04` | 电量 | 扳手到 App | 已解析百分比，实测收到 |
| `0x05` | 发状态到 App | 扳手到 App | 已加入接收入口 |
| `0x06` | 应答 | 扳手到 App | 已解析为“应答正常/设备拒绝”，实测收到 |
| `0x10` | 参数设置 | App 到扳手 | 危险写入，默认不自动发送 |
| `0x11` | 手机控制 | App 到扳手 | 可组包发送 |
| `0x12` | 扭矩转角过程数据 | 扳手到 App | 已解析员工号、螺栓号和点列，驱动曲线 |
| `0x15` | 最终结果 | 扳手到 App | 已解析状态、扭矩、角度、上下限 |
| `0x17` | 结果确认 | App 到扳手 | 只在收到 `0x15` 后自动发送 |
| `0x21` | 请求校时 | 扳手到 App | 收到后自动回复 `0x22` |
| `0x22` | 时间校准 | App 到扳手 | 只在收到 `0x21` 后自动回复 |
| `0x23` | 螺母计数 | 扳手到 App | 已解析选项 |
| `0x25` | 查询 SN | App 到扳手 | 已组包，实测可收到回包 |
| `0x26` | 应答 SN | 扳手到 App | 已解析设备编号，实测收到 |
| `0x33` | 连接保活 | App 到扳手 | TCP 连接后周期发送 |
| `0x44` | GPS | 扳手到 App | 已解析有效标志和文本 |
| `0x50` | RC283F 参数设置 | App 到扳手 | 危险写入，默认不自动发送 |
| `0x51` | RCH 参数设置 | App 到扳手 | 危险写入，默认不自动发送 |
| `0x55` | 特殊模式结果 | 扳手到 App | 已解析状态、扭矩、角度 |

说明书没有列出“读取当前参数设置”的独立回读帧。目标扭矩、目标角度等值可从最终结果 `0x15` 中读取；实时过程 `0x12` 提供扭矩和角度点列。


## 解析口径

`0x12` 扭矩角度过程帧：

```text
员工号 10 bytes ASCII
螺栓号 2 bytes unsigned big-endian
重复点：扭矩 2 bytes + 角度 2 bytes
```

当前 Android 代码按整数解析：

```text
torqueNm = torqueRaw.toDouble()
angleDeg = angleRaw.toDouble()
```

如果真实设备联调发现角度或扭矩放大 10 倍，必须回到说明书和抓包重新确认缩放。

`0x15` 最终结果帧：

```text
状态码位于第 5 字节，即帧结构中的第一个保留字节
员工号
螺栓号
年月日时分秒
模式
目标扭矩
实际扭矩
目标角度
实际角度
扭矩上限
扭矩下限
角度上限
角度下限
```

收到 `0x15` 后必须发送 `0x17` 结果确认。

`0x55` 特殊模式结果帧：

```text
状态码
员工号
螺栓号
年月日时分秒
模式
目标扭矩
实际扭矩
实际角度
```

`0x55` 扭矩字段按说明书口径 `/10`。

## 实测记录

已验证真实设备：

```text
心跳应答  C5 C5 FF 06 FF FF 01 00 8E
设备 SN   C5 C5 FF 26 FF FF 05 01 00 00 00 01 B4  -> 0100000001
电量      C5 C5 FF 04 FF FF 01 64 F0              -> 100%
```

本轮外置网卡直连已收到 `0x15` 最终结果 2 帧，能同步目标扭矩、实际扭矩、目标角度、实际角度和上下限。暂未收到 `0x12` 过程点列和 `0x55` 特殊模式结果。

Android TCP 连接后应立即发送一次连接检查和设备编号查询，成功后界面显示设备编号。该操作只读，不改变扳手参数。

## 保活策略

旧调试中发现空 TCP 连接可能被设备关闭，因此 TCP 连接建立后必须发送保活。说明书写“每分钟发送”，实测调试工具使用更短间隔可保持设备醒着。Android 当前 `TcpWrenchClient` 默认 `heartbeatIntervalMillis = 60_000`，现场联调可根据设备表现缩短。

## 安全边界

- 不在 App 启动后自动正转。
- 不在 App 启动后自动反转。
- 不自动写入参数。
- 正转、反转、参数设置必须加入现场确认和二次确认。
- 不把 `0x17`、`0x22` 做成普通手动按钮；这两个帧只能在设备先发来结果或校时请求后自动回复。
- 调试阶段优先使用真实扳手的空载或低风险安全场景。
