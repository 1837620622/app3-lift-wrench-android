## 1. 下一位开发者先看这里

**背景（再写一遍）：** 不造新扳手。用厂家定制工业扳手 + Wi‑Fi/TCP，服务浮置板**隔振器顶升与调频**；厂家给不出可靠平衡点，故本阶段做**实时扭矩可视化、协议内远程全控制、带原生图的 Excel 全量导出**以攒数据；**平衡点算法是下一步**。

继续修改现有 Kotlin Android 工程，不换框架，不做 Windows。默认 GitHub Actions 构建。用户会继续改需求——**当前以文档交接为主，勿擅自大规模重写或 push**。

产品优先级（详见[界面与导出优化方向](界面与导出优化方向.md)）：
1. 横屏单屏无竖滚 + Mac/iOS 工业观感 + Wi‑Fi 优先；
2. **正式界面安全远程控制**（0x11→0x01 正/反/停、参数；与「结束采集」文案分离）；
3. 可读实时扭矩–转角（**按转角跨度自适应**显示窗口）；
4. **xlsx + 原生 Excel 图表**（设置可选 CSV）；
5. 无硬件金样例/Mock 多轮测；真机后再锁缩放；
6. 数据量够了再做算法内嵌。
7. **交付次序：** 真实可运行 UI 验收通过后，方可制作贴合实机的高端宣传静帧与营销向动态；禁止以概念渲染代替软件验收，禁止功能点流水账式硬导览。文档阶段不产出宣传片。

不要只换皮或只出效果图。正式界面不得出现「模拟」采集入口。

## 2. 项目要解决什么问题

项目用于浮置板钢弹簧隔振器的顶升检测与**调频相关载荷调整**。隔振器数量多、测点多，需要可重复试验。扳手为**厂家定制设备**（非本仓库硬件开发）；工业手机负责连接、**远程控制**、采集、显示、记录和带图导出。厂商不能可靠给出平衡点，故先积累全过程扭矩/转角数据，算法后置。

机械装置通过顶升螺杆、顶紧结构和支撑体系对隔振器施加载荷，上部扭矩扳手提供驱动及扭矩/转角数据。

现场有多个隔振器、多个测点需要依次检测。同一个测点也需要重复试验，后续会积累较多数据。软件要帮助工人正确连接设备、采到完整过程、清楚观察变化，并能将不同试验的数据带走分析。

最终研究目标是利用全过程数据识别临界分离状态，研究能否据此估计隔振器原本承担的支承力。用户平时把这一目标称为“测力、找到平衡点”。这不是只把一个扭矩数字显示成力值，也不是把曲线画平就算成功。

本次软件工作不重新设计扳手机械内部、电机、减速器、三角支架或下部接口，不修改 CAD 来迁就软件。约 500 N·m 是机械装置的目标能力，不能用于证明软件换算出的力值准确。

## 3. 被测对象和采集工具必须分开

- 被测对象：某个项目、线路/区间、浮置板、隔振器或测点。
- 采集工具：使用的某台扭矩扳手，由设备 SN 等信息标识。
- 网络入口：工人连该工具的 Wi-Fi；TCP **自适应探测**（默认先试 `192.168.4.1:7888`，再候选/短扫并缓存成功端点），正式界面不填、不选端口；测点编号不是网络参数。
- 测量记录：某个测点的某次加载过程，有独立记录 ID，可重复、可追溯。

目标数据层级：项目/线路/区间 → 板号 → 隔振器/测点 → 多次加载记录。当前 UI 已提供板号、测点及独立会话；完整的项目层级和批量试验管理仍待完善。

可以使用一台扳手依次检测多个隔振器，也可能更换多台遵守相同协议的扳手。不能把换 Wi-Fi、换工具与换测点混为一谈，不能把不同机器或不同试验直接拼成同一条分析曲线。

## 4. “采集平衡点”应怎样解释

扳手直接回传的是扭矩和转角，协议中没有一个已经计算好的“平衡点”字段。软件需要先采完整加载数据，再结合力值标定和独立试验判断临界状态。

一个便于理解的过程是：

1. 安装好工具，确认测点及试验条件，进行低速、连续加载。
2. 最开始可能存在空行程；工具接触后开始明显承载。
3. 随工具顶升力增加，原支承接触承担的力逐步转移到工具。
4. 在准静态且没有额外传力路径的条件下，弹簧当时的支承力由工具顶升力和原支承接触力共同平衡。
5. 原接触力降到零附近、原支承接触面刚分离，就是要核对的临界事件。
6. 扭矩—有效转角曲线可能在附近发生斜率变化，软件可据此寻找候选点，再验证该候选是否对应实际分离。

必须区分以下概念：

| 概念 | 含义 | 不能直接等同于 |
| --- | --- | --- |
| 扭矩 | 扳手测量通道回传的旋转力矩 | 轴向顶升力 |
| 工具顶升力 FD | 工具在加载中施加的轴向力 | 原始支承力 F0 |
| 临界分离力 Fc | 原支承接触刚分离时的工具力 | 最终峰值或任意平台值 |
| 原始支承力 F0 | 检测前隔振器承担的支承力 | 未验证的 Fc |
| 曲线拐点 | 数据趋势发生变化的位置 | 已确认的物理分离事件 |
| 数据断点/间断 | 断线、暂停、反转、换螺栓等导致的段边界 | 应跨过去连续拟合的普通点 |

若分离前已经发生额外弹簧压缩，临界力也未必等于原始支承力。摩擦变化、工具变形、速度变化、滑移、接触粘连等都可能影响曲线，不能强行找一个水平平台或最大值作为结论。

用户的“断点”表述需要在设计中兼顾两类内容：要观察的临界转折候选，以及通信或工况造成的数据间断。两者的图形、标记和解释要区分。

## 6. 工人使用流程

打开软件 → 在系统中连接扳手 Wi-Fi → App **自适应探测** TCP（默认先试 `192.168.4.1:7888`，正式界面不填、不选端口/IP）→ 确认测点 → **启用远程控制** → 正转/反转/停止并观察扭矩、转角和曲线 → 结束本次采集（必要时先停扳手） → **导出带原生图的 Excel**（可另存 CSV） → 新建下一条测量记录。

要求：

- 工人不需要理解十六进制协议、缩放系数或内部线程。
- 常用操作直接可见，不为看实时曲线反复跳页。
- 连接设置、历史、诊断与主测量页面分工清楚。
- 采集开始/结束与设备正反转、机械制动、急停分开表达；**远程启停进入正式界面**，运动指令需确认。
- “结束采集”不能使工人误以为机械一定停止；停止扳手必须是明确的 0x01 停止（在已启用远程后）。
- 板号和测点不能随意覆盖已经采到的数据；重复试验保留独立记录。
- 断线或暂停后保留已采数据，清楚标识保留值，不能继续冒充实时值。

## 7. Wi-Fi 和更换设备的要求

后续可能更换扳手机器，但厂家通信协议暂时不变。不要硬编码某个扳手 Wi-Fi 名称或 SSID 前缀作为唯一准入条件。

目标 Wi-Fi 名称由用户自定义并在本机记住。它用于引导用户去系统连接，不是让软件改写设备广播名称，也不构成协议兼容或连接成功证明。

软件需提供：

- 可编辑的目标 Wi-Fi 名称。
- 系统 Wi-Fi 设置入口和清晰操作引导。
- 当前 Wi-Fi 信息，无法读取时如实提示。
- **主路径自适应探测** TCP host/port（工人不选手动端口）；高级诊断才可编辑设备 IP 和端口。
- 按真实 TCP 建链及 **C 协议合法报文**判断是否通信成功（握手成功才算就绪）。
- 不因 SSID 被系统隐藏、权限不足或名称改变就直接锁死采集。

当前默认端点保留 `192.168.4.1:7888`（必须先试）。自适应探测应复用/强化默认网关、候选端口与短时子网扫描逻辑；握手成功后记住上次成功端点。不同厂家设备的实际端点仍可能变化——**靠探测，不靠工人猜端口**。

每次连接建立独立会话。SN 真正回传后补写到本次会话；没有回传就保持未知，不能拿上一台工具的 SN 冒充。

## 8. 最新视觉要求：工业用途，macOS/iOS 感受

用户明确要求界面全面重新设计，越简洁越好，但不是删掉必要信息；希望视觉、字体、布局和交互接近 macOS/iOS，清晰、细腻、自然、顺滑。

具体方向：

- 浅中性色和清晰层级，有限强调色，避免整片发黑、乱配色、复杂背景和装饰性渐变。
- 数字、单位、标签和说明使用统一字体层级；避免粗重巨大标题、到处加粗、字距和基线混乱。
- 中文字体也要实际检查。不能为了模仿 Apple 而违规打包受限字体；可采用系统字体或合法可分发字体。
- 主曲线拥有足够的宽度和高度，不能被大按钮、重复读数和状态卡片挤成一条细带。
- 大字体、短高度横屏、系统导航栏和安全区域都要验收。
- 控件触控范围足够，视觉尺寸与触控尺寸合理，按钮用途明确。
- 动效主要用于状态反馈和必要的界面过渡，不使用装饰动画干扰测量，不通过动画制造采集点。
- 正式界面不出现“模拟”等相关字眼，也不提供假数据模式。调试入口目前需要保留在独立位置，完善后在正式版隐藏。
- 不用颜色掩盖布局问题，不用一张生成图片代替可运行界面。

内部可以制作测试画面、使用合成场景、渲染预览，但只用于开发与自动测试。要按真实渲染结果反复修正，包括数据很多、发生转折、数据间断、无数据、断线和大字体等状态。

## 9. 可视化验收要求

### 9.1 基础信息

实时扭矩与转角醒目，单位准确。主图应清楚表达扭矩—转角关系，轴名、刻度、量程和图例不能依赖猜测。未标定时不能把空力值、默认压力或位移占位放成主结果。

### 9.2 转折、间断和交互

- 对曲线拐点/临界候选提供可辨认的标识，说明其是否只是参考、人工标记或算法候选。
- 不把普通上升、斜率变缓或一条水平线直接标成“平衡点已确认”。
- 发生断线、暂停、反转、换螺栓或工况切换时，需评估分段显示，不能无条件跨段连线和拟合。
- 应能查看曲线局部点值、关键位置和必要的前后段；可通过点选、游标、缩放或合适交互实现，具体方案按实际手机体验确定。
- 后续人工标记或算法结果要能追溯到原始记录，不能只有装饰性圆点和没有实际行为的按钮。

### 9.3 实时性和大量数据

- 连上扳手后以真实回传数据更新曲线。
- 区分已连接、等待过程点、实时更新、回传暂停和停止后的保留数据。
- 心跳存在不代表有新的过程点。
- UI 渲染、数据库写入和导出不能长时间阻塞主线程。
- 显示可以有窗口、抽样或分层加载，但不能丢掉数据库和导出里的原始点。
- 抽样显示必须保留必要关键形态并说明其口径，不把插值误作测得点。
- 明确可见范围与全量记录的关系，不能让工人误认为只剩最近若干点。

## 10. 数据保存与导出

至少保留会话 ID、测点信息、工具编号、接收顺序、扭矩、原始/显示角度、接收时间和原始 HEX。方向、有效转角、工况、标定版本等未由协议直接提供的信息不能猜测，必要时后续扩展表单和 schema。

用户最初提到 XLSX，中期以 CSV 满足基线；**2026-11-05 锁定：详细 `.xlsx` + 原生 Excel 图表为主，设置中可选 CSV**。因此：

- 过渡期完整会话 CSV 仍保留。
- 下一阶段必须生成真实 `.xlsx` 并内嵌**原生图表**（非仅 PNG、不能改扩展名）；清单与 POI 选型见[界面与导出优化方向](界面与导出优化方向.md)。
- CSV 要有中文编码处理、正确转义、稳定字段与清楚单位。
- 不能只导出图表最后 50 个点。
- 按数据库分页、冻结导出上界，避免后续采集点混入同一次快照。
- 不在主线程把大量数据拼成一个巨大字符串。
- 导出失败应处理未完成文件，并清楚反馈；不得静默显示成功。
- 原始数据和人工/算法结果分开，未测量或未持久化的字段留空，不伪造 0 或实时状态。

当前 Android 10+ 优先写系统下载目录（代码里仍为 `WifiWrenchExports`，**待随产品改名一并改为 WiFiWrenchExports 等**），旧系统或回退路径使用应用专属 Documents。用户自选保存位置、统一分享入口和更完整导出体验仍需完善。

## 11. 算法路线和必须保留的边界

### 11.1 扭矩到顶升力

优先整机实测标定。例如同一组件、润滑和低速正向工况下，检验 `Tw = a·Fref + b`，其中 a 为正、单位为 N·m/kN。通过验证后使用 `FD = (Tw − b) / a`。若稳定非线性确有依据，再使用单调分段标定。

未标定、超范围或工况不匹配，不输出正式力值。不要重复补偿已经包含在整机标定内的内部传动比。默认效率、摩擦、面积和传动比不能当现场实测参数。

机械资料保留 M48×3 方向；单线导程暂按 3 mm/rev 理解，但须结合实物确认。旧 EngineeringCalculator 内仍有 5 mm 默认导程等公式自检值，不能直接用于生产换算。

转角对应的螺杆进给不等于浮置板实际抬升量，手机陀螺仪的工具姿态也不能替代输出轴真实转角。

### 11.2 候选分离点

先筛选有效加载段，再在扭矩—有效转角曲线上识别候选，避免标定折线本身制造假拐点。

可检验的模型是连续两段线性关系：

`T(x) = β0 + m1·x + (m2−m1)·max(0, x−c)`

遍历候选 c，限制两侧最小样本数和角度跨度；与单直线模型比较残差改善，检查前后斜率、候选位置稳定性及工况事件。阈值由试验确定，不把开发默认值当工程标准。

单直线已能解释数据、候选靠近边界、与停转/滑移重合、标记不足或数据断续时，应返回“未识别”，不能强行输出。

在线识别需要转折后的足够数据，存在确认延迟；不能宣称在刚分离的瞬间无延迟识别。

### 11.3 实测验证

用独立力值参考做标定和验证，再用真实接触间隙/相对位移检验候选分离事件。标定与验证按整次加载划分，不能把同一曲线相邻点随机拆成训练和验证。

记录不同载荷水平、重复试验、独立装配、润滑、速度、温度、组件和标定版本。区分局部开口与整体卸载。数据量大不自动等于力值或算法正确。

当前代码没有已经通过实测验证的自动分离点算法，也没有可靠的完整拐点交互 UI。不要在接手时误写为已完成。

## 12. 协议要求

根目录 `最新协议.docx` 是授权保留的厂家原文。协议不因界面重做或 Wi-Fi 名称变化而修改。

- TCP 字节流。
- 基础帧：`C5 C5 | 地址 | 功能 | 保留两字节 | 长度 | 数据 | 累加和`。
- 保留既有拆包、粘包、半包、长度和校验处理。
- 0x12：扭矩/角度过程；0x15：普通结果；0x55：脉冲等结果。
- 其他已有电量、状态、SN、心跳、结果确认和按请求校时的处理继续保留。
- 普通过程、普通结果与设定帧、脉冲结果的缩放口径不同，禁止全局统一除以 10。
- 0x12 不含逐点设备时间戳。当前同帧各点保存手机接收时间，按数据库 id 保留顺序；不能假定每个点相隔 1 ms。
- 不自动发送正转、反转或参数写入。设备动作不与普通采集按钮混用。
- 真正换厂家设备时，仍需核对端点、协议细节和实测缩放，不能只凭“协议好像一样”宣布兼容。

## 13. 构建、版本和调试

- GitHub Actions 负责单元测试、Lint、Debug/Release 变体编译、APK、模拟器测试和证据上传。
- 自动测试尽量覆盖真实软件流程，但测试环境中使用的合成数据不进入运行数据源。
- 实际扳手 Wi-Fi、测量精度、采样节奏、机械加载和标定仍由真实硬件联调验证。
- 当前版本基线 0.2.0；CI versionCode 为 `1000 + github.run_number`，调试 versionName 包含 code。
- 调试应用 ID 为 `com.chuankangkk.wrenchlift.debug`，正式 ID 不带 `.debug`。
- 主线 CI 固定调试签名存在 GitHub Secrets，不提交签名文件、密码或密钥，也不上传这些内容为 Artifact。
- 调试与正式包可并存，旧应用的数据不自动复制；不能让用户先卸载旧包丢弃数据来掩盖签名或升级问题。
- 当前需要独立调试/诊断入口，产品完善后正式版隐藏。现有入口已由 BuildConfig.DEBUG 控制，但交互与诊断体验仍可改进。
- 每次交付必须核对安装包内部版本号、应用 ID、签名和实际构建来源，不能只给文件改名。
