# 产品背景与用户需求

本文件集中记录当前产品方向，供其他 Agent、开发工具和后续维护者直接导入。需求描述与已实现、已验证状态必须分开；最新代码、测试与 Actions 结果是实现状态的依据。

## 使用背景

装置在浮置板钢弹簧隔振器的顶升试验中工作。上部使用 T 型扭矩扳手，工业手机在现场横屏显示测量信息。软件首先解决工人容易连接、采集真实数据、清楚看到变化和完整带走数据的问题。它不是扳手控制器的替代品，也不能靠界面本身证明测力精度。

用户希望先积累大量加载过程数据，再通过数据和独立试验计算候选分离点，研究其与原始支承力的关系。不能为了界面看起来完整而伪造力值、平衡结果或设备未提供的时间信息。

## 多个隔振器的检测任务

检测对象是现场多个隔振器及其测点，不只是演示一把扳手的数字。可用一台扳手依次检测多个位置，也可能更换或使用多台遵守同一协议的扳手。软件需区分“被测隔振器”和“采集工具”，不能把 Wi-Fi 名称、扳手编号当作隔振器编号。

组织数据的目标层级是项目/线路/区间 → 浮置板板号 → 隔振器或测点编号 → 本次加载记录。工具 SN 标识使用哪台扳手；同一测点可重复测量，每次记录应能独立追溯、导出和比较。当前 UI 提供板号/测点及独立会话，项目层级的完整管理仍需后续完善。

每次连接开启独立会话，换扳手或重连都不把新点接到上次曲线上。设备 SN 在真实回传后补写入本次会话；没有回传则保持未知，不拿上台设备的编号冒充。未产生测量数据的连接尝试不在工人的测量记录列表中展示。

## 用户所说的“采集平衡点”怎样理解

扳手直接提供扭矩和转角，软件不是直接收到一个“平衡点”字段。目标是通过加载过程找到原支承接触面刚分离附近的临界状态，再确认该时刻的力值能否估计隔振器原来承担的支承力。

可按以下过程向使用者解释：

1. 先安装顶升工具，记录本次隔振器位置、扳手及试验条件，进行低速、连续加载。
2. 初始可能有空行程；工具接触并承载后，顶升力增加，原支承接触承担的力逐渐转移到工具。
3. 在准静态、无额外传力路径的条件下，弹簧支承力由工具顶升力和原支承接触力共同平衡。原接触力降到零附近，就是要核对的分离事件。
4. 这一事件可能表现为扭矩—有效转角曲线斜率变化，但不一定出现水平平台。不能把曲线变平、最大的扭矩或最后一个点直接叫作平衡点。
5. 软件先保留原始全过程，用连续分段拟合提出候选分离角和对应扭矩；标定有效时才换算候选临界力。
6. 用独立测力参考、接触间隙或相对位移核对候选事件。只有误差和重复性满足实际要求，才将其进一步解释为初始支承力估计。

因此，用户需要采集的是完整加载数据，平衡点/分离点是后续基于数据和试验依据判断的结果。多次、多位置数据可用于检查重复性、摩擦差异和算法稳定性，不能用大量未区分工况的数据自动证明算法正确。

每次试验还应逐步补充组件/螺杆、润滑、转速、温度、装配、标定版本、有效加载段和人工观察记录。当前协议不能直接提供的字段，未来可通过试验表单补录；未补录的就记为未知，不由程序猜测。

## 当前平台决策

- 保留现有 Kotlin + Jetpack Compose Android 技术栈，主要重新设计 UI 和数据流程，不从头更换语言。
- 当前仅完成 Android。Windows 放在后续单独阶段，届时可以采用其他语言；不提前引入跨平台迁移或提供假的 EXE 打包任务。
- 本机不需要安装 Android/JDK/Gradle/模拟器环境，使用 GitHub Actions 构建 APK 和自动测试。
- 用户可以自行安装 APK 在真实手机和扳手上测试。Actions 模拟器尽量覆盖可自动化的软件行为，但不能声称替代真实硬件联调。

## 工人操作流程

打开软件 → 检查目标 Wi-Fi 和测点 → 到系统连接设备 Wi-Fi → 连接并采集 → 观察扭矩、转角与曲线 → 结束采集 → 导出完整 CSV → 新建下一条记录。

主页面要能在短高度横屏手机上使用，不让工人为看实时数据翻找多层页面。常用操作少、名称明确、控件可触达，大字体也不裁掉按钮。不把通讯诊断、原始报文、参数写入和多种工程公式堆在同一个屏幕。

“结束采集”意味着软件断开连接，不意味着机械停机。不能让工人把软件记录按钮误认为可靠的扳手制动或急停。

## 可更换设备和 Wi-Fi 引导

设备可能更换，Wi-Fi 名称可能随厂家、机器或配置而变化；通讯协议暂时不变。不得以固定厂牌、固定 SSID 前缀或旧设备名称限制可连接设备。

目标 Wi-Fi 名称由用户自定义并在本机记住。名称只用来引导用户去系统连接，不改写设备广播名称，也不充当协议兼容或连接成功证明。软件保留系统 Wi-Fi 入口和设备 IP/端口设置。

Android 在权限不足时可能读不到当前 SSID。应提示无法读取，不伪称当前已经连到目标名称；最后通过 TCP 建链和真实有效帧判断设备通信。不要因 SSID 不可见就锁死采集。

## 视觉、动态与实时性

默认横屏、宽屏布局，白色或浅中性色背景、清晰轴线与数字、有限强调色。不要背景场景图、复杂装饰或重复卡片挤压有效曲线。

主页面优先扭矩和转角以及扭矩—转角曲线。连接、测点、采集状态和导出入口清楚可见，设置与历史独立进入。当前未实现可靠的分离点自动算法，应显示待数据分析，不能把曲线变缓标记为已确认平衡。

内部渲染/预览采用真实 Compose 界面的模拟器截图：空数据、合成数据曲线、短横屏和大字体状态都要检查，按截图修正布局。图像不代替可运行代码，也不使用 AI 效果图冒充软件截图。

动态图表必须反映实际收到的点；不为流畅而补造测量点或把插值当测量。连接状态可有短暂的颜色过渡，页面切换和控件反馈应克制，不使用装饰动画干扰观察。

区分“已连接”“等待过程数据”“实时回传”“过程数据暂停”“采集停止后保留数据”。心跳成功不代表正在产生过程点。以过程帧接收时间标识新鲜度，暂停后数值可以保留，但不能继续标成实时。

显示层需要有界窗口以避免大量点拖慢手机。持久化和导出必须保留全部点；后续要查看全量曲线时采用按需查询和可说明的显示抽样，不截断原始数据。

## 数据与计算

保存原始扭矩、原始角度、显示角度、帧接收时间、数据库顺序、会话、螺栓号和原始报文，以及可追溯的有效状态。协议没有逐点采样时间时，不增加人工毫秒冒充采样时刻。

支持 CSV 全会话导出，Excel 可直接打开；当前优先实现 CSV，若未来增加 XLSX，应输出真实工作簿。导出要有明确截止点和分页，不能只导出页面最后 50 个点，也不能在 UI 线程加载整场巨大字符串。

大量数据用于后续标定和分离点研究。算法按独立可测试模块开发，考虑承载起点、有效正向段、中断/反转/滑移、连续分段拟合、候选稳定性和拒绝输出。对应力值需实测标定和独立验证。具体物理边界见[算法路线](算法路线.md)。

## 调试、版本与安装

当前需要好用的调试入口，能看到网络、报文与设备状态，以便用户安装后反馈。调试工具独立于工人测量页。产品完善后隐藏正式版调试入口，当前已经按 BuildConfig.DEBUG 区分；这不表示正式发布和签名体系已经全部完成。

每个现场测试包必须能识别版本与构建号。主线 CI 使用固定的调试签名 Secrets，便于连续覆盖更新。调试包与正式包应用 ID 分开，不能通过卸载旧应用来掩盖签名错误并丢失旧数据。
