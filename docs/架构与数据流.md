# 架构与数据流

## 平台与入口

Android minSdk 26，目标 SDK 35，编译 SDK 36.1。AGP 9.2.1 使用内置 Kotlin，Compose 编译插件 2.2.10；不要再随意叠加旧 Kotlin Android 插件。CI JDK 21，Java/Kotlin 运行目标保留现有 JVM 17 兼容设置。

MainActivity 请求网络信息所需权限，WrenchLiftApp 观察 MeasurementViewModel.state。工人入口 WorkerWorkbench 是以状态和回调驱动的 Compose 页面；原 BigScreen 位于调试内容插槽。

## 采集链

TcpWrenchClient → WrenchPacketParser → WrenchPacket → MeasurementViewModel.handlePacket → 功能解码 → Room 原始点 + 最近点显示。

connectTcp 包含 Android 网络诊断、端点发现、建链、连接检查和 SN 查询。TCP 自身负责拆/粘包后的完整帧流及心跳。设备启停、参数写入不进入自动建链流程。取消与关闭 socket 不能导致旧 reader 关闭新连接。

0x12 内部每点包含扭矩/角度，无设备逐点时间。记录的 timestampMillis 是帧的手机接收时间；同帧相同，以入库 id 排序。旧记录的人工递增时间不被重写。不要使用此字段直接推导设备采样周期。

## 数据层

Room schema 保留版本 3，提供 2→3 迁移，不使用 destructive fallback。TorquePointEntity 保存 sessionId、接收时间、螺栓号、原始/工程角度、扭矩、可空力和压力、原始帧及人工标记。MeasurementEntity 存储会话元信息和最终结果。模式、角度与设备状态的完整追溯仍以原始帧为依据。

MeasurementViewModel 用 measurementMutex 串行保护当前帧处理和导出快照边界。界面 recentPoints 保留最近 50 点；persistedPointCount 是本次进程显示计数，不能替代数据库统计或导出行数。收到结果帧时会保留结果点，不应未经依据去重为过程点。

会话不是按最终结果自动拆分；一个会话可以包含多次设备结果，以螺栓号/原始帧区分。新建按钮仅在离线时使用，保留旧会话，清空当前显示和 sessionId。对于自动按试验拆分、滑移/反转/暂停段标记和持久化分析有效角度，仍需后续设计。

## 导出链

exportCurrentCsv 选择当前 sessionId；历史页以 id 选择指定会话。先在互斥边界内读取元信息和 MAX(point.id)，随后在 IO 调度器按 id 游标读取至上界，每页最多 1000 点。CSV 直接写入 Writer，不加载完整大数组。采集后续点仍入库，但不改变本次上界。

导出优先 Android 10+ MediaStore Downloads/App3Exports，失败可回退应用专属 Documents/App3Exports。失败删除未完成输出，导出中的 IS_PENDING 完成后才清除。Android 8/9 的专属文件访问和分享仍需后续改善。

文本单元格转义 CSV 特殊符号并防止 Excel 公式解释。导出保留旧字段位置；未实施的位移以及没有持久化的逐点预警状态留空，压力继续使用数据库可空值，不能把占位 0 解释为实际测得位移。历史导出不填写当前 Wi-Fi/IP 冒充过去网络信息；对应字段为空。

## 调试与正式版

BuildConfig.DEBUG 控制唯一工人入口中的调试菜单。正式版保留通讯能力和内部诊断所需代码，但不向工人显示该菜单。进一步删减调试代码及正式签名发行是后续步骤。

## 测试分工

src/test：协议示例、帧解析、TCP 回环、数据库标记与超过两页的 2505 点快照、标定越界、CSV 格式及趋势描述。
src/androidTest：设置/记录导航、连接回调、导出禁用/启用、横屏控件显示和真实 Compose 截图。数据用合成样例，与实测分开。

需要现场验证：扳手无互联网 Wi-Fi 下的路由、权限、后台生命周期、长时传输、跨连接边界、实际标定及设备动作。没有这些证据，不得把模拟器通过当整机通过。
