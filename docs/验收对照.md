## 1. 连接（§10.1）

| 清单项 | 实现 | 自检证据 |
| --- | --- | --- |
| 工人主路径无端口/IP 输入或选择 | 工作台、引导页、测点页、设置页均无端口/IP；仅「设置 → 高级诊断」可看/改 host:port | `WorkerScreensTest.workbenchHasSixControlsAndNoPortOrIpOnMainScreen` / `guideAndSplashHaveNoPortField` / `portsOnlyAppearInAdvancedDiagnostics`；`WorkerTextTest` 扫描全部工人文案不含端口/IP/TCP/协议码 |
| 连 Wi‑Fi 后自适应探测；默认先试 `192.168.4.1:7888` | `WifiNetworkTracker` 监听 Wi‑Fi → 自动 `startProbe`；`EndpointPlanner.primary`：无缓存时第一个就是默认端点 | `EndpointPlannerTest.firstSessionTriesFactoryDefaultFirst` |
| 默认失败时自动换候选/短扫 | 候选主机（缓存/默认/手动保存/网关）× 候选端口（7888/8899/9000/10001 等）并行 TCP 检查 → 逐个握手；仍失败再扫 192.168.4.x 子网 | `AdaptiveConnectorTest.changedPortIsFoundThroughCandidatesWhenDefaultRefuses` / `silentTcpPortIsNotTreatedAsHandshake…` |
| C 协议握手成功后记住上次成功端点；下次优先复用 | 握手 = 发 0x33 + 0x25 后收到任一**校验通过的 C 协议帧**（不以 TCP SYN 为准）；成功写 `last_good_host/port`；下次 `primary = [缓存, 默认]` | `AdaptiveConnectorTest.lastGoodIsReusedBeforeDefault`；`RemoteGateViewModelTest` 断言 `lastGoodEndpoint` |
| 引导页无端口栏；高级诊断才可查看/编辑 | `ConnectGuideScreen` / `DiagnosticsScreen` | 截图 `guide-no-wifi`、`diagnostics` |
| 无蓝牙主路径 | 无蓝牙代码与权限 | 源码检查 |

补充：
- 只有 TCP 能连、扳手 1.8 s 内不回话时：保持连接显示「已接通，等扳手回话」，**首个合法帧到达才算握手并缓存**（`ProbeOutcome.TcpOnly`）。
- 扳手热点不能上网时系统可能把默认路由留在移动数据：扳手 socket 绑定到 Wi‑Fi 网络（`Network.bindSocket`）。**未在真机验证。**
- 断线后自动重探 3 次（每次新会话）；「结束会话」后不再自动连。

## 6. 已知限制 / 待办

1. 没有真机：Wi‑Fi 绑定 socket、握手时延、0x12 实际频率与缩放、正转对应顶升方向都需现场确认。
2. 子网短扫只覆盖 192.168.4.x（沿用既有安全范围）；扳手换网段时靠网关候选 + 手动端点。
3. 远程状态是 App 侧记录（协议无可靠回读）；0x05 状态位未解析成方向灯。
4. 0x50/0x51 脉冲参数未实现。
5. CI workflow 仍指向 `App3Android` 符号链接（缺 `workflow` 权限，见接手说明）。
6. 图标/启动页主体位图来自 design-renders 示意稿，待产品方定稿替换。
